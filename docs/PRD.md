# 飲食記錄 App — 產品需求文件（PRD）

- 版本：v1.1（MVP + 食物庫）
- 日期：2026-11-01（v1.1：2026-11-03）
- 狀態：v1 已上線；v1.1 食物庫開發中

---

## 1. 概述

一個給家庭自用的飲食記錄 PWA。每位成員可用**拍照**或**文字**記錄每天吃了什麼，由 AI 辨識食物並估算熱量與三大營養素，再依個人的身體資料與目標產生**每日總結**。

### 1.1 使用者與情境

- 使用者：本人與老婆兩人（資料結構不限人數，日後可加入其他家人）。
- 兩人各自用自己的手機，登入**同一個家庭帳號**，看到同一份資料。
- 每個人的餐點**各自拍照、各自記錄**，不做「一筆記錄分給多人」。

### 1.2 目標

1. 用最少操作記下一餐（拍照 → 確認 → 存檔）。
2. 讓每個人知道今天吃了多少、和自己的目標差多少。
3. 由 AI 給出友善、具體、可執行的每日建議。

---

## 2. 範圍

### 2.1 MVP 包含

- 家庭帳號登入（單一帳號）
- 成員檔案管理（新增／編輯／封存）
- 體重歷史紀錄
- 每日熱量目標自動計算（可手動覆寫）
- 拍照記錄與手動文字記錄，皆經 AI 解析
- AI 結果確認與編輯
- 每日 AI 總結
- 歷史檢視：日曆、熱量長條圖、體重折線圖
- 本月 API 花費估算
- 模型切換

### 2.2 MVP 不包含

- 資料匯出
- 每週／每月總結
- 離線使用
- 多帳號、個人帳號、權限分級
- 膳食纖維、糖、鈉等營養素
- 一筆記錄分給多位成員
- 自訂主題配色
- 多語系（只做繁體中文）

## 3. 功能需求

### 3.1 帳號與登入

| 項目 | 規格 |
|---|---|
| 帳號 | 單一家庭帳號，Email + 密碼 |
| 註冊 | 關閉公開註冊，帳號由管理者在 Supabase 後台建立 |
| Session | 長效登入（約 30 天免重新登入） |
| 裝置預設成員 | 每支手機在本機（localStorage）記住「預設成員」，開啟 app 時自動切換到該成員，可隨時改 |

### 3.2 成員檔案

| 欄位 | 必填 | 說明 |
|---|---|---|
| 名稱 | ✅ | 顯示名稱 |
| 性別 | ✅ | 男／女（用於 BMR 公式） |
| 出生年月 | ✅ | 年齡由系統自動計算 |
| 身高（cm） | ✅ | |
| 體重（kg） | ✅ | 建檔時寫入第一筆體重紀錄 |
| 活動量 | ✅ | 久坐／輕度／中度／高度 |
| 目標 | 選填 | 減重／維持／增肌，預設「維持」 |
| 飲食備註 | 選填 | 自由文字，例如「素食」「乳糖不耐」「控制血糖中」，提供給 AI 參考 |
| 每日熱量目標覆寫 | 選填 | 填寫後取代自動計算值 |

- 刪除成員改為**封存**：隱藏不顯示，資料保留，可還原。

### 3.3 體重紀錄

- 每位成員有體重歷史（日期 + 體重）。
- 計算熱量目標時用**最新一筆**體重。
- 可新增、編輯、刪除單筆紀錄。

### 3.4 每日熱量目標

1. **BMR**（Mifflin-St Jeor）
   - 男：`10 × 體重kg + 6.25 × 身高cm − 5 × 年齡 + 5`
   - 女：`10 × 體重kg + 6.25 × 身高cm − 5 × 年齡 − 161`
2. **TDEE** = BMR × 活動係數

   | 活動量 | 係數 |
   |---|---|
   | 久坐 | 1.2 |
   | 輕度 | 1.375 |
   | 中度 | 1.55 |
   | 高度 | 1.725 |

3. **每日目標** = TDEE + 目標調整（減重 −500、維持 0、增肌 +300）
4. 如果有手動覆寫值，以覆寫值為準。
5. 三大營養素目標（預設比例，日後可調）：蛋白質 25%／碳水 50%／脂肪 25%（以熱量換算為克數：蛋白質與碳水 4 kcal/g、脂肪 9 kcal/g）。

### 3.5 飲食記錄

#### 3.5.1 一筆記錄（Entry）

- 屬於**一位成員**、**一個日期**、**一個餐別**。
- 餐別：早餐／午餐／晚餐／點心。新增時依當下時間自動帶入，可手動修改：

  | 時段（台灣時間） | 預設餐別 |
  |---|---|
  | 05:00–10:29 | 早餐 |
  | 10:30–14:29 | 午餐 |
  | 14:30–16:59 | 點心 |
  | 17:00–20:59 | 晚餐 |
  | 21:00–04:59 | 點心 |

- 可以補記過去的日期。
- 「一天」以台灣時間 00:00–23:59 劃分。

#### 3.5.2 拍照記錄

- 每筆最多 **3 張**照片，另可加**選填的文字補充**（例如「飯只吃一半」「醬料沒吃」）。
- 照片在**手機端**壓縮到長邊約 1024px 再上傳。
- 照片和文字補充一起交給 AI 辨識。
- 照片會**保留**，在記錄詳情和歷史中可以查看。

#### 3.5.3 手動輸入

- 自由文字，例如「一碗牛肉麵加一顆滷蛋、一杯無糖綠茶」。
- 交給 AI 解析成品項清單，進入和拍照相同的確認畫面。

#### 3.5.4 AI 辨識結果與確認畫面

AI 回傳一份品項清單，每個品項包含：

| 欄位 | 說明 |
|---|---|
| 名稱 | 例如「白飯」 |
| 份量描述 | 例如「1 碗（約 200g）」 |
| 熱量（kcal） | |
| 蛋白質（g） | |
| 碳水（g） | |
| 脂肪（g） | |

使用者可以：

- 新增品項、刪除品項
- 修改名稱或份量描述後，按「重新估算」讓 AI **只重算該項**
- 直接修改熱量和三大營養素的數字
- 確認後存檔

#### 3.5.5 失敗處理

- AI 呼叫失敗（網路、逾時、API 錯誤）時，照片和文字先存成 **「待分析」** 狀態，不會遺失。
- 「待分析」記錄可以手動重試；app 下次開啟時也會自動重試。
- 不做離線功能：沒有網路時直接提示無法送出。

#### 3.5.6 從食物庫選（v1.1）

- 「＋」選單多一個「從食物庫選」：搜尋食物 → 選份量 → 加進清單，可以一次加多項。
- 不呼叫 AI，存檔後直接是「已確認」。
- 選食物畫面最上方先列出這位成員**最近常吃**的食物，點一下就以上次的份量加入。
- AI 確認畫面的每個品項可以：
  - **從食物庫替換**：AI 認錯時直接換成食物庫的食物，不再花 token。
  - **存成常用食物**：把 AI 估過的品項存成家庭自訂食物，下次直接選。

### 3.9 食物庫（v1.1）

目的：讓使用者自己選食物、填份量，減少 AI token 用量。

| 來源 | 說明 |
|---|---|
| 官方 | 衛福部食藥署「食品營養成分資料庫」開放資料（約 2,000 項，每 100g），以 migration 匯入，所有家庭共用、唯讀 |
| 家庭自訂 | 例如照包裝營養標示建立的「無加糖豆漿 1 瓶」，或從 AI 結果存下來的品項 |

- 每項食物有一個**基準份量**與其營養素：官方資料是「100g」；自訂食物可以是「1 瓶（450g）」或沒有克數的「1 碗」。
- **份量單位**：基準份量的克數已知時可以直接輸入公克，另有常用單位（例如「1 碗 = 200g」「1 顆 = 55g」）。常見食物預設幾個單位，家庭可以自己新增。
- 搜尋比對名稱與俗名（例如搜「空心菜」找得到「蕹菜」）；自訂食物排在官方資料前面。
- 設定頁可以管理自訂食物（新增、編輯、刪除）。
- 這一階段 AI 辨識**不**參考食物庫，避免提示變長反而增加 token。

### 3.6 每日總結

- **觸發**：使用者按「產生今日總結」才產生，可以重新產生。
- **提供給 AI 的資料**：
  - 成員檔案（性別、年齡、身高、活動量、目標、飲食備註）
  - 當日熱量與三大營養素目標
  - 當日所有記錄（依餐別）
  - 最近 7 天的每日攝取總量
  - 最近的體重紀錄與趨勢
- **內容**：
  1. 當日攝取和目標的比較（熱量、三大營養素）
  2. 飲食評語（優點與可改善的地方）
  3. 明天的具體建議
- **風格**：繁體中文、口吻友善不說教、篇幅控制在一個手機畫面內。
- **過期標示**：產生後如果當天記錄有新增、修改或刪除，總結上會標示「記錄已變更，可重新產生」。
- 每位成員每天只保留**最新一份**總結。

### 3.7 歷史檢視

- **日曆**：選任一天，查看該天的記錄與總結。
- **熱量長條圖**：最近 7 天／30 天的每日熱量，標出目標線。
- **體重折線圖**：體重歷史。

### 3.8 設定

- 成員管理（新增、編輯、封存、還原）
- 體重紀錄管理
- AI 模型選擇：Sonnet 5.5（預設）／Opus 5.5／Haiku 5.5
- 本月預估 API 花費（依每次呼叫記下的 token 用量計算）
- 本機預設成員
- 我的食物（自訂食物管理）
- 登出

## 4. 畫面

底部分頁列：**今天／歷史／設定**

```
│ 碳水   █████░ 150/230g       │

├──────────────────────────────┤
│ 早餐                  420kcal│

│ 晚餐                         │
│ 點心                         │
├──────────────────────────────┤

│                         (＋) │
├──────────────────────────────┤
│   今天   │   歷史   │   設定  │
└──────────────────────────────┘
```

- 「＋」按鈕：選擇「拍照」、「手動輸入」或「從食物庫選」。
- 「待分析」的記錄在列表中有明顯標示和重試按鈕。

### 4.2 記錄流程

1. 按「＋」→ 選「拍照」或「手動輸入」
2. 拍照（最多 3 張）或輸入文字，可加補充說明
3. 確認日期與餐別
4. 送出 → AI 分析中（顯示 loading）
5. 確認畫面：編輯品項 → 存檔

### 4.3 歷史

- 上方：日曆（有記錄的日期有標記）
- 下方：熱量長條圖（7 天／30 天切換）、體重折線圖
- 點日期 → 進入該天的「今天」畫面

### 4.4 設定

- 成員、體重、AI 模型、本月花費、本機預設成員、登出

### 4.5 外觀

- 配色跟著手機系統的淺色／深色模式。
- 以手機直式操作為主。

## 5. 資料模型（初稿）

```
households
  id, name, created_at

members
  id, household_id, name, sex, birth_year_month,
  height_cm, activity_level, goal, diet_note,
  calorie_target_override, archived_at, created_at

weight_logs
  id, member_id, date, weight_kg, created_at

entries
  id, member_id, date, meal_type, note,
  status (pending | analyzing | ready | failed),
  created_at, updated_at

entry_photos
  id, entry_id, storage_path, sort_order

entry_items
  id, entry_id, food_id (nullable), name, portion,
  kcal, protein_g, carbs_g, fat_g, sort_order

foods                       -- v1.1；household_id 為 null 表示官方資料
  id, household_id, source (tfda | custom), source_code,
  name, aliases, category, description,
  base_label, base_grams (nullable),
  kcal, protein_g, carbs_g, fat_g,  -- 基準份量的營養素
  created_at

food_portions               -- 常用單位；household_id 為 null 表示預設
  id, food_id, household_id, label, grams

daily_summaries
  id, member_id, date, content,
  generated_at, is_stale

ai_usage_logs
  id, household_id, model, purpose (recognize | re_estimate | summary),
  input_tokens, output_tokens, cost_usd, created_at

settings
  household_id, ai_model
```

- 所有資料表透過 Supabase Row Level Security 限定只有該家庭帳號可存取。
- 照片存放在 Supabase Storage 的私有 bucket，以簽名網址讀取。

## 6. AI 設計

| 用途 | 輸入 | 輸出 |
|---|---|---|
| 照片／文字辨識 | 照片（≤3）、文字補充、成員飲食備註 | 品項清單（結構化 JSON） |
| 單項重新估算 | 品項名稱、份量描述 | 單一品項的營養數值（結構化 JSON） |
| 每日總結 | 見 3.6 | 繁體中文文字 |

- 供應商：Claude API，預設模型 **Sonnet 5.5**，可在設定切換 Opus 5.5／Haiku 5.5。
- 辨識結果使用 **structured outputs**，保證回傳格式正確。
- 程式中抽出一層 AI 供應商介面，日後可替換成其他服務（例如 Ollama）。
- API key 只存在伺服器端環境變數，前端永遠拿不到。
- 每次呼叫記錄 token 用量到 `ai_usage_logs`。

### 6.1 預估花費（Sonnet 5.5：輸入 $2、輸出 $10／每百萬 token）

- 一次照片辨識約 US$0.02，一份總結約 US$0.03。
- 兩人每天約 8 筆記錄 + 2 份總結：**約 US$5–7／月**。

## 7. 技術架構

| 層 | 選擇 |
|---|---|
| 前端 | Nuxt（TypeScript），PWA |
| UI | Nuxt UI（Tailwind） |
| 圖表 | Chart.js + vue-chartjs |
| 後端 | Nuxt server routes（Nitro） |
| 部署 | Vercel（免費方案） |
| 資料庫 | Supabase Postgres |
| 照片 | Supabase Storage |
| 登入 | Supabase Auth（Email + 密碼） |
| AI | Anthropic Claude API（官方 TypeScript SDK） |

### 7.1 免費方案限制

- Supabase 免費專案連續 7 天沒有使用會暫停；每天使用就不會被暫停。
- Supabase Storage 1GB：每張約 150KB、每天約 8 張，大約可以用 2 年。

## 9. 需要使用者自行完成的事項
